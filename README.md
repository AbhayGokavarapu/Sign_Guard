## What is SignGuard?

SignGuard answers one question: **"Can I trust this PDF? Has it been tampered with after it was digitally signed?"**

It integrates:
- **Genuine pyHanko CMS cryptographic verification** — mandatory, not optional
- **PDF revision analysis** using startxref-based discovery (not raw %%EOF scanning)
- **Multi-quality Error Level Analysis** (Q65/75/85/95 sweep)
- **ORB + RANSAC** copy-move / duplication detection
- **Automatic signature localisation** via classical computer vision
- **Rule-based explainable evidence fusion** — no machine learning
- **Hash-chained tamper-evident audit log** (atomic writes)

The system does **not** use a trained ML/DL model. Every decision is traceable to a specific algorithm output.

## Analysis pipeline

```
PDF Upload
  ↓ validate_pdf() — size/page/format limits
  ↓ parse_pdf() — SHA-256 hash, metadata, page images
  ↓ classify() — CRYPTOGRAPHICALLY_SIGNED / VISUAL / UNSIGNED / UNSUPPORTED
  ↓ crypto_verify() — pyHanko CMS, ByteRange (7 structural checks)
  ↓ revision_analyze() — startxref-based discovery, text/metadata diff
  ↓ localize() — greyscale→text mask→Otsu→morph→components→crops
  ↓ run_ela() — Q65/75/85/95 sweep + selected quality
  ↓ orb_match() + ransac_verify() — keypoints, Hamming, RANSAC
  ↓ fuse() — rule-based verdict + integrity_verdict (no CLEAN)
  ↓ append_record() — hash-chained audit log (atomic write)
  ↓ JSON report + PDF report download
```

## Verdicts

| Verdict | Trigger | Note |
|---|---|---|
| ⚠️ **TAMPERING DETECTED** | Cryptographic integrity failure confirmed | Critical finding |
| ⚠️ **REVIEW REQUIRED** | Shadow suspect, visual duplication, elevated ELA | Manual review needed |
| ❓ **INCONCLUSIVE** | No signatures or insufficient evidence | Not "clean" — just unresolved |
| ⛔ **UNSUPPORTED** | Document unprocessable | |

**CLEAN has been removed.** A self-signed test certificate cannot establish document authenticity or signer identity, so returning CLEAN was misleading.

Separate **integrity status**:
- `NO TAMPERING DETECTED` — signed bytes intact
- `INTEGRITY FAILURE` — signed bytes modified
- `INTEGRITY NOT ESTABLISHED` — verification incomplete
- `NOT APPLICABLE` — unsigned document

## Six attack scenarios

| ID | Attack | Visual difference | Key detection |
|---|---|---|---|
| A | Original signed | None (no attack) | Shows conservative INCONCLUSIVE — test cert means no identity established |
| B | Byte tampering | Pages look identical — only SHA-256 differs | ByteRange digest mismatch → CRYPTO-001 CRITICAL |
| C | Shadow attack | Left: $1,000 signed; Right: $9,000 current | Pixel diff + text diff → SHADOW-001 HIGH |
| D | Visual duplication | Two near-identical signature boxes | ORB inliers → ORB-001 MEDIUM |
| E | ELA manipulation | Pages nearly identical — ELA heatmap shows residuals | Elevated mean residual → ELA-001 MEDIUM |
| F | Unsigned | No signature present | INCONCLUSIVE — absence ≠ forgery |

## Limitations (explicitly documented)

1. **Python 3.14 / pyHanko margin** — pyHanko targets Python 3.9–3.12. Some math-validity paths return UNKNOWN on Python 3.14. Full results require Python ≤3.12.
2. **ELA on rendered PDFs** — may not reflect original JPEG compression history of embedded content.
3. **Shadow detection** — uses one rendering engine; attacks with identical renders are undetectable.
4. **ORB/RANSAC visual similarity** — does not establish signer identity or prove unauthorised reuse.
5. **Heuristic localisation** — confidence scores are heuristic, not calibrated probabilities.
6. **Synthetic evaluation only** — does not establish real-world generalisation.
7. **No IoU localisation metrics** — requires ground-truth bounding-box annotations.
8. **No browser automation screenshots** — dashboard verified manually.
9. **No dependency vulnerability audit** — offline environment.
10. **This is a research/educational tool** — results require expert review for any legal or operational use.
